# 막대 하나로 오리 파이프라인 한 바퀴

강화학습을 처음 하는 사람이 **Mac CPU만으로** 오리 학습에 쓰는 라이브러리를 하나씩 손에 익히는 튜토리얼이다.
주제는 처음부터 끝까지 **CartPole(수레 위 막대 세우기)** 하나다. 몸이 단순해서 학습이 10초 안팎에 끝난다.

## 목표

다 마치면 오리 학습 설정 파일(`microduck_rl`)을 열었을 때 "이건 몸 정의, 이건 관측, 이건 보상 항목, 이건 PPO 설정" 하고 읽히는 상태가 된다.

## 단계

| 단계 | 문서 | 하는 일 | 익히는 것 | 오리에서는 |
|---|---|---|---|---|
| 0 | [MuJoCo XML로 몸 만들기](00-mujoco-xml.md) | XML 30줄로 수레와 막대를 만들고 뷰어로 밀어 보기 | MuJoCo, MJCF | 오리 로봇 XML |
| 1 | [Python으로 시뮬레이션 돌리기](01-mujoco-python.md) | 관측·보상·종료 함수를 짜고 무작위 행동으로 돌려 보기 | `mujoco` Python API, MDP 개념 | mjlab의 관측·보상·종료 항목 |
| 2 | [rsl_rl PPO로 학습하기](02-rsl-rl-ppo.md) | 환경 64개를 묶어 PPO로 학습, 학습 곡선 보기 | rsl_rl, PyTorch, TensorBoard | `train`, `tb` |
| 3 | [ONNX로 내보내 재생하기](03-onnx-play.md) | 정책 파일을 뷰어에서 재생 | ONNX, onnxruntime | `export`, 정책 재생, duck-sim |

0~3단계는 직접 짠 코드로, 4단계는 오리와 같은 틀(mjlab)로 한다. 0~3단계에서 손으로 만든 부품이 4단계에서 mjlab의 어느 설정 조각이 되는지 맞춰 보는 게 마지막 과제다.

## 각 문서를 읽는 법

모든 단계 문서는 같은 순서로 되어 있다.

1. **목표**와 **알아 둘 개념**: 짧게 읽는다.
2. **실습**: 뼈대 코드를 파일로 만들고 `TODO` 부분을 직접 채운다.
3. **확인**: 기대하는 출력과 비교한다.
4. **더 해 보기**: 숫자를 바꿔 결과가 어떻게 달라지는지 본다. 이해가 가장 많이 느는 부분이다.
5. **정답**: 접혀 있다. 막혔을 때만 연다. 정답 코드는 2026-11-20에 이 Mac(M4, CPU)에서 그대로 돌려 확인했다.
6. **오리와 연결**: 방금 한 것이 오리 학습의 어디에 해당하는지.

## 준비

### 1) 실습 폴더 만들기

이 저장소 루트에 실습 폴더를 만든다. 다른 곳에 만들어도 된다.

```sh
cd ~/Projects/microduck
mkdir rl-tutorial && cd rl-tutorial
uv init --python 3.12 --name rl-tutorial
rm main.py                      # uv init이 만든 예제 파일, 필요 없음
```

### 2) 라이브러리 설치

```sh
uv add "mujoco==3.10.0" "rsl-rl-lib==5.0.1" torch tensorboard onnx onnxscript onnxruntime
```

| 패키지 | 쓰는 단계 | 하는 일 |
|---|---|---|
| `mujoco` | 0~ | 물리 엔진과 뷰어 |
| `rsl-rl-lib` | 2~ | PPO 학습기. 오리 학습(mjlab 1.3.0)과 같은 5.0.1로 고정 |
| `torch` | 2~ | 신경망. rsl_rl이 내부에서 쓴다 |
| `tensorboard` | 2~ | 학습 곡선 보기 |
| `onnx`, `onnxscript` | 3 | 정책을 ONNX 파일로 내보내기 |
| `onnxruntime` | 3 | ONNX 정책 실행(로봇에서 쓰는 방식) |

버전을 고정한 이유: rsl_rl은 판이 바뀔 때마다 설정 형식이 크게 바뀐다. 5.0.1 기준으로 쓴 코드는 다른 판에서 돌지 않을 수 있다. mjlab은 4단계에서 따로 설치한다.

설치 확인:

```sh
uv run python -c "import mujoco, rsl_rl, torch; print(mujoco.__version__, torch.__version__)"
```

### 3) 학습 결과는 저장소에 올리지 않기

학습 결과(`logs/`)와 가상환경(`.venv/`)은 커밋하지 않는다. `rl-tutorial/.gitignore`에 이렇게 적는다.

```
.venv/
logs/
__pycache__/
```

## 알아 두면 좋은 것

- **실행은 항상 `uv run ...`** 으로 한다. 실습 폴더의 가상환경을 알아서 쓴다.
- **Mac에서 뷰어 창을 Python 코드 안에서 띄울 때는 `python` 대신 `mjpython`** 을 쓴다(`uv run mjpython play.py`). macOS는 창을 메인 스레드에서만 그릴 수 있어서 MuJoCo가 따로 준비한 실행기다. 3단계에서 쓴다.
- **CPU 부담**: 0~3단계는 가볍다(학습 10초 안팎). 4단계 mjlab은 CPU에서 느리게 도는 GPU용 엔진이라 몇 분 걸릴 수 있다. 이 Mac에서 무거운 작업을 돌리다 멈춘 적이 있으니, 4단계는 문서에 적힌 작은 크기로만 돌린다.

## 용어집

| 용어 | 뜻 | 이 튜토리얼에서 |
|---|---|---|
| 환경(environment) | 에이전트가 행동하고 결과를 받는 세계 | 수레와 막대가 있는 MuJoCo 시뮬레이션 |
| 관측(observation) | 에이전트가 보는 숫자 | 수레 위치·속도, 막대 각도·각속도 |
| 행동(action) | 에이전트가 내는 숫자 | 수레를 미는 힘 (-1~1) |
| 보상(reward) | 행동이 얼마나 좋았는지 나타내는 점수 | 쓰러지지 않고 곧게 서 있으면 +, 가운데에서 멀어지면 − |
| 에피소드 | 시작부터 끝(넘어짐 또는 시간 초과)까지 한 판 | 최대 500스텝 = 10초 |
| 정책(policy) | 관측을 받아 행동을 내는 함수. 학습 대상 | 64-64 크기 신경망 |
| 가치 함수(critic) | "지금 상태에서 앞으로 받을 보상 합"을 예측하는 신경망. 학습을 돕는다 | 정책과 같은 크기 신경망 |
| PPO | 정책 경사 계열 알고리즘. 로봇 학습의 표준 | rsl_rl의 `PPO` |
| 할인율 γ (gamma) | 먼 미래 보상을 얼마나 덜 쳐 줄지 | 0.99 |
| 시뮬레이션 스텝 vs 정책 스텝 | 물리는 0.01초마다, 정책은 0.02초마다 계산 | decimation = 2 |
